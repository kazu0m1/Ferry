# Ferry v1.1.1 prototype 1 テスト

## 目的
Windows Explorerで観察した「Pasteで追加・更新されたトップレベル項目を選択状態にし、何を貼り付けたかを利用者へ示す」挙動をFerryへ追加する。

## A. Build / version
- [ ] `Build.cmd` 成功
- [ ] Window title = `Ferry - prototype 1`
- [ ] About/version = `1.1.1-prototype1`

## B. 基本 Copy → Paste
1. Folder Aで既存file/folderを3件選択して`Ctrl+C`。
2. 既存itemも入っている別Folder Bへ移動して`Ctrl+V`。
- [ ] Pasteで追加された3件だけが選択される。
- [ ] Bにもともと存在した無関係itemは選択されない。
- [ ] Paste完了後も選択が残る。
- [ ] true background clickで通常どおり選択解除できる。

## C. Cut → Paste
- [ ] `Ctrl+X` → `Ctrl+V`でも移動先itemが選択される。
- [ ] sourceからitemが消え、destinationだけが選択される。

## D. List / Grid
- [ ] ListでPasteした結果が選択される。
- [ ] GridでPasteした結果が選択される。
- [ ] Paste直後にList ⇄ Gridを切り替えても同じPaste結果集合が選択される。

## E. 衝突系
- [ ] 同一folder内Copy → PasteでWindowsが生成したcollision-safe name（例: Copy / (2)相当）が選択される。
- [ ] 既存fileへの置換を選んだ場合、実際に更新されたdestination itemが選択される。
- [ ] Folder mergeでも更新されたトップレベルfolderが選択される。
- [ ] Skipしただけの既存itemを誤って「貼付結果」として選択しない。

## F. 大きめPaste / 視覚フィードバック
- [ ] 複数または大きめのitemをPasteし、処理中にincremental refreshが走る環境では、現れたPaste結果が順次選択される。
- [ ] 処理中に選択されたitemは完了後も最終集合として残る。
- [ ] full-list flicker / crashがない。

## G. v1.1.0 selection回帰
- [ ] List/Grid通常rubber-band
- [ ] Ctrl / Shift / Ctrl+Shift rubber-band
- [ ] true-background clear後のArrow / Shift+Arrow
- [ ] Selection Anchor表示
- [ ] 選択済みitem D&D
- [ ] List/Grid autoscroll
- [ ] List ⇄ Gridの選択集合維持

## 判定
A〜Gの必須項目がPASSしたらprototype 2またはRC候補へ進む。
