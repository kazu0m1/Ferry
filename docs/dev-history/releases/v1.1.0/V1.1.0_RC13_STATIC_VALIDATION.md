# Ferry v1.1.0 RC13 — Static Validation

**Date:** 2026-09-15  
**Candidate:** `1.1.0-rc13`  
**Baseline:** v1.1.0 RC12 diagnostic

## RC12 log evidence

ユーザー実機logでは、`Down`直前に以下を確認した。

- selectedCount = 0 / selectedIndex = -1
- ListView本体が`IsKeyboardFocused=True`
- focus = ListView selector
- Ferry SelectionAnchor = index 0
- WPF LastActionItem = index 20
- CollectionView CurrentItem = null / CurrentPosition = -1

`Down`処理後はWPF LastActionItemがindex 77（末尾）へ移動した。したがってRC11の「item containerへfocusを戻す」だけでは、virtualizationを含むSelector-focus経路を閉じられないことが確定した。

## Source inspection

### `MainWindow.cs`

- `TabViewContext.KeyboardNavigationItem`を追加。
- Selectorに`GotKeyboardFocus` routed handlerを追加し、最後にfocusを持ったitemを記録。
- item MouseDown時にもnavigation originを記録。
- `TryHandleEmptySelectionArrowNavigation`を追加。
- plain `Up`/`Down`のPreviewKeyDownで、
  - Selector本体focus
  - 0件選択
  - valid navigation originあり
  の場合だけWPF default navigationを止め、隣接itemへsingle selection / scroll / focus / anchor同期を行う。
- itemへfocusが戻った後の通常keyboard navigationは従来WPF経路へ戻す。
- diagnosticsに`keyboardOrigin`を追加。
