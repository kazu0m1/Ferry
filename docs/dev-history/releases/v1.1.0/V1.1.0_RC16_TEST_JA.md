# Ferry v1.1.0 RC16 — 実機確認

対象: `1.1.0-rc16`  
目的: RC15で残った「通常Arrow後に破線Selection Anchorが1 item遅れる」問題を修正し、RC15でPASSしたbackground-clear経路を回帰させていないことを確認する。

## 0. ビルド・起動

- [ ] `Build.cmd` が成功する。
- [ ] `Portable\Ferry.exe` が起動する。
- [ ] Window title = `Ferry - RC 16`。
- [ ] About / version表示がある場合は `1.1.0-rc16` と整合する。

## 1. 最重要A — RC15 off-by-one再現経路

1. List表示で連続したファイルを10件以上表示する。
2. 1行目 A を通常クリックする。
3. Shiftを押さず、`↓`を1回ずつ5～6回押す。各キーの間を一瞬空けて目視する。
4. 各移動ごとに「青い選択行」と「破線Selection Anchor」を確認する。
5. たとえばFまで到達したら、そこで初めて`Shift+↓`を1回。
6. さらに`Shift+↓`を2回。
7. `Shift+↑`を1回。

期待:
- [ ] A→Bの最初のDown直後から、選択・keyboard focus・破線anchorがすべてB。
- [ ] 以後B→C→D…でも破線が常に現在行と一致し、1 item前に残らない。
- [ ] Fから最初の`Shift+↓`でF/G。
- [ ] 続けてF～H、F～IとFを起点に伸びる。
- [ ] `Shift+↑`でendpoint側だけ1件縮む。
- [ ] Shift範囲中は破線anchorがFに残る。
- [ ] viewport端へのjump / freezeなし。

※ この項目は可能ならRC15で撮影したのと同じフォルダ・同じ操作で比較する。

## 2. 最重要B — true background clear後の無修飾Down（RC13/15回帰）

1. 1行目Aを通常クリック。
2. scrollbar / wheelだけで末尾へ移動する。
3. 最終itemより下の完全空白を通常クリックし、0 selectedにする。
4. `↓`を1回。
5. さらに`↓`を3回。

期待:
- [ ] 最初のDownでBが選択されfocusもBへ移る。
- [ ] 破線anchorもBに一致する。
- [ ] 続けてC/D/Eと1件ずつ進み、破線も同じ現在行。
- [ ] 末尾へjumpしない。

## 3. 最重要C — true background clear後のShift+Down（RC15回帰）

1. Aを通常クリック。
2. 完全空白を通常クリックして0 selected。
3. `Shift+↓`を1回。
4. 続けて`Shift+↓`を2回。
5. `Shift+↑`を1回。

期待:
- [ ] 最初にA/Bが選択される。
- [ ] anchorはA、keyboard endpoint/focusはB。
- [ ] A～C、A～Dへ1件ずつ伸びる。
- [ ] Shift+UpでA～Cへ1件縮む。
- [ ] 末尾へjumpしない。

## 4. 最重要D — Up方向の対称性

1. 末尾Zを通常クリック。
2. 完全空白で0 selected。
3. `↑`を1回、さらに3回。

期待:
- [ ] Z-1、Z-2、Z-3…と1件ずつ上へ進む。
- [ ] 選択/focus/破線anchorが常に現在行で一致。
- [ ] 先頭へjumpしない。

4. 再度Z → 完全空白 → `Shift+↑`。

期待:
- [ ] Z-1とZの2件が選択される。
- [ ] anchorはZ、endpointはZ-1。

## 判定

### PASS
特に1～4がすべて期待どおりで、Selection Anchorの1-item遅延が消えている。

### HOLD
以下のどれか:
- 破線anchorが選択/focusより1件遅れる、または先行する。
- background clear後にviewport端へjump。
- Shift範囲のanchorが現在keyboard originと食い違う。
- Gridに新しいnavigation回帰。

失敗時は項目番号、操作、実際の結果、再現率を報告。必要な場合のみ診断ログ版を作る。
