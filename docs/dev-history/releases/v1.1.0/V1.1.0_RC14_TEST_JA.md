# Ferry v1.1.0 RC14 — 最終実機確認手順

**基準:** v1.1.0 RC13（keyboard-navigation fix 実機PASS）  
**目的:** RC13の修正を維持したままdiagnostic loggingを外したRC14を、v1.1.0 final昇格前の最終候補として確認する。

> 重要: RC14ではRC12/RC13の強制診断logは出しません。通常のDebug Logging設定へ戻しています。
> 全項目PASSなら追加log提出は不要です。失敗した場合は、失敗した項目番号・実際の挙動・再現性（毎回/時々）を記録してください。必要なら次に専用diagnostic版を作ります。

---

## 0. 準備・ビルド（必須）

1. RC14を新しいfolderへ展開する。RC13の`Portable`やbuild outputを上書き流用しない。
2. `Build.cmd`を実行する。
3. `Portable\Ferry.exe`を起動する。
4. Window titleを確認する。
5. SettingsでDebug Loggingを明示的にONにしていない限り、新規`Ferry.log`が強制生成されないことを確認する。

期待:
- [ ] `Build.cmd`成功。
- [ ] Ferry正常起動。
- [ ] title = **`Ferry - RC 14`**。
- [ ] Debug Logging OFFならRC12/RC13のような強制navigation logは出ない。

テスト用folder:
- 20件以上のitemがあり、List表示で縦scroll可能。
- 末尾itemの下にtrue background（完全空白）が見えるfolderが望ましい。
- 可能ならRC13で使用した同じfolderを使う。

# Part I — keyboard jump修正の必須回帰

## 1. 元の再現経路: 先頭 → true background → Down（最重要 / release blocker）

1. List表示にする。
2. viewportを一番上へ移動。
3. 一番上のitem **A（index 0）** を通常クリック。
4. Aが選択され、Selection Anchorの破線がAにあることを確認。
5. itemを追加クリックせず、mouse wheelまたはscrollbarだけで一番下まで移動。
6. 末尾itemより下の**完全空白**を通常クリック。
7. statusが0 selectedになったことを確認。
8. **Downを1回だけ**押す。
9. 続けてDownを5回程度押す。

期待:
- [ ] 手順6でselectionは0件になる。
- [ ] 手順8で末尾へjumpしない。
- [ ] viewportは先頭付近へ戻り、**Aの次item（index 1）** が1件選択される。
- [ ] keyboard focusはそのtarget itemへ入る。
- [ ] その後のDownはindex 2, 3, 4...と1件ずつ自然に進む。
- [ ] freeze / 数秒の停止 / viewportの往復がない。

判定: [ ] PASS  [ ] FAIL
