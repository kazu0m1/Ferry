# Ferry v1.1.0 RC15 — 実機確認

対象: `1.1.0-rc15`  
目的: RC14で残った keyboard navigation / Shift+Arrow の不整合を、Explorer実機観察に合わせて最終確認する。

## 0. ビルド・起動

- [ ] `Build.cmd` が成功する。
- [ ] `Portable\Ferry.exe` が起動する。
- [ ] Window title = `Ferry - RC 15`。
- [ ] About / version表示がある場合は `1.1.0-rc15` と整合する。

## 1. 最重要A — 通常Arrow後のShift+Arrow起点

Explorer実機観察の再現確認。

1. List表示で連続したファイルを10件以上用意する。
2. 1行目 A を通常クリックする。
3. `↓`だけを数回押し、たとえば6行目 F まで移動する。Shiftはまだ押さない。
4. 各`↓`のたびに、選択行と破線Selection Anchorが同じ現在行へ移動することを確認する。
5. F に到達したところで `Shift+↓` を1回。
6. さらに `Shift+↓` を2回。

期待:
- [ ] 通常Arrow中、破線anchorが古いAに残らず現在行へ追随する。
- [ ] 最初の`Shift+↓`で F/G が選択される。
- [ ] 続けて押すと F～H、F～I のようにFを起点として伸びる。
- [ ] A～Iのように最初のmouse clickまで巻き戻った範囲にならない。
- [ ] Shift範囲中は破線anchorがFに残る。
- [ ] viewportが先頭/末尾へjumpしない。

## 2. 最重要B — true background clear直後のShift+Down

Explorer実機観察では `Aを選択 → 完全空白で0件 → Shift+Down` は A/B 選択になる。

1. 1行目 A を通常クリック。
2. itemをクリックせず、必要ならscrollbar / wheelだけで末尾へ移動。
3. 最終itemより下の完全空白を通常クリック。
4. statusが0 selectedであることを確認。
5. `Shift+↓` を1回。

期待:
- [ ] A/B の2件が選択される。
- [ ] viewportはA/Bが見える位置へ戻る。
- [ ] Selection AnchorはA。
- [ ] keyboard current/focusはB。
- [ ] 末尾へjumpしない。

続けて:
6. `Shift+↓` を2回。
7. `Shift+↑` を1回。

期待:
- [ ] A～Dまで1件ずつ伸びる。
- [ ] `Shift+↑`で1件だけ縮む。
- [ ] anchorはAのまま。

## 判定

### PASS
上記に明確な回帰がなく、特に1～4がExplorer実機挙動と一致。

### HOLD
以下のいずれか:
- true background後のArrow / Shift+Arrowでviewport端へjump。
- 通常Arrow後のShift範囲が古いmouse anchorから始まる。
- 破線Selection Anchorと実際のkeyboard range originが食い違う。
- Gridで新しいnavigation回帰。

失敗時は、項目番号・操作手順・実際の結果・再現率を報告。必要な場合だけ診断ログ版を作る。
