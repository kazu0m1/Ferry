# Ferry v1.1.0 RC1 — 実機確認項目

基準線：Prototype 27 + Ctrl+L Breadcrumb復帰

今回の変更範囲は、Ctrl+Lで表示されるLocation Boxの終了経路とRC1版表示のみです。Rubber-band / Selection / D&D / Autoscroll / List⇄Grid同期はPrototype 27のままです。

## A. Ctrl+L → Esc

1. Listで任意のitemを1件選択する。
2. `Ctrl+L`。
3. Breadcrumbが消え、現在パスがLocation Boxに全選択状態で表示されること。
4. `Esc`。

期待結果：
- Location Boxが閉じる。
- Breadcrumbが復帰する。
- もともとのitem選択は解除されない。
- もともとのitemへkeyboard focusが戻る。
- 直後に↑/↓を押すと、そのitemの隣から正常に移動する。

## B. Ctrl+L → Ctrl+L（再押下）

1. itemを1件選択する。
2. `Ctrl+L`。
3. Location Box表示中に、もう一度`Ctrl+L`。

期待結果：
- Location Boxが閉じる。
- Breadcrumbが復帰する。
- item選択は維持される。
- 直後の↑/↓が元のitemから正常に続く。

## C. Gridでも同じ

- A/BをGrid viewでも各1回確認する。
- Esc/再押下後に選択tileとkeyboard操作が破綻しないこと。

## D. Enter navigation回帰

1. `Ctrl+L`。
2. 存在する別フォルダのパスを入力してEnter。

期待結果：
- Location Boxが閉じる。
- 指定フォルダへ移動する。
- Breadcrumbが新しいパスへ更新される。

## E. 無効パス

1. `Ctrl+L`。
2. 存在しないパスを入力してEnter。

期待結果：
- `Folder not found.` が表示される。
- Location Boxは編集可能なまま残る。
- EscでBreadcrumbへ戻れる。

## F. Esc既存動作の境界

- Location Boxを開いていない通常状態でEscを押した場合、従来のFerryのEsc処理が変わっていないこと。
- Search中のEsc動作が変わっていないこと。

## G. Prototype 27 最小回帰

- true background clickで選択解除。
- 通常rubber-band 1回。
- Ctrl rubber-band 1回。
- 選択済みitemのD&D 1回。
- List⇄Grid切替後も選択集合が一致。
- Selection Anchor破線：anchorを残したまま↑/↓移動したとき、破線がanchorに残る。
