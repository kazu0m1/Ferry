# Ferry v1.1.0 RC16 — Static Validation

**Candidate:** `1.1.0-rc16`  
**Environment limitation:** Windows / .NET Framework 4.8 runtime build is not available in the assistant environment. Validation below is static only.

## Scope

RC16 changes only the timing/location of ordinary unmodified Up/Down anchor synchronization. Empty-selection recovery from RC15 is intentionally unchanged.

## Static checks

- [PASS] Window title source = `Ferry - RC 16`.
- [PASS] `AssemblyInformationalVersion` = `1.1.0-rc16`.
- [PASS] `Make-PortableRelease.cmd` version = `1.1.0-rc16`.
- [PASS] Window registers both `PreviewKeyDown` and bubble-phase `KeyDown` with handled events enabled.
- [PASS] RC15 `SchedulePlainArrowAnchorSync` / `DispatcherPriority.Input` path is removed.
- [PASS] Bubble handler acts only on unmodified Up/Down while file-view Selector has keyboard focus within.
- [PASS] Bubble handler requires exactly one selected item before syncing ordinary Arrow destination.
- [PASS] Current item is resolved from the single selected item first, focused item as fallback, avoiding deferred-focus timing ambiguity.
- [PASS] Shift+Arrow does not enter ordinary Arrow anchor synchronization.
- [PASS] RC15 empty-selection Arrow/Shift+Arrow helper remains present.
- [PASS] No forced diagnostic logging added.

## Runtime items requiring Windows validation

- Dashed Selection Anchor is on the same row as selection/focus after every discrete plain Arrow.
- Plain Arrow followed by Shift+Arrow starts exactly from the current row, not one row behind.
- `A -> background clear -> Down` remains B without edge jump.
- `A -> background clear -> Shift+Down` remains A/B.
- Up direction is symmetric.
- Grid navigation remains natural.
- Existing Shift+Click, rubber-band and D&D behavior remains intact.
