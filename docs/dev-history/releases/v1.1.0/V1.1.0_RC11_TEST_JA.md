# Ferry v1.1.0 RC11 — 実機確認項目

**基準:** 公開直前のv1.1.0 final candidate  
**目的:** true backgroundで選択解除した後のkeyboard navigation edge-jumpを局所修正し、既存selection挙動に回帰がないことを確認する。

---

## A. 今回の再現手順（最重要）

1. List表示で、画面内にtrue background（itemに属さない完全空白）がある状態を用意する。
2. 一番上など任意のitem Aを通常クリックする。
3. Aにkeyboard focus/currentがある状態でtrue backgroundを通常クリックする。
4. selectionが0件になったことを確認する。
5. `↓` を1回押す。続けて `↑` も試す。

期待:
- [ ] true background click直後は0件選択のまま。
- [ ] ListView全体がkeyboard navigationの起点になって遠い端へ飛ばない。
- [ ] `↓` / `↑` は直前のfocused itemを基準に自然に移動する。
- [ ] 一瞬で先頭/末尾へscrollしない。
- [ ] 大量item folderでも長いfreezeを伴わない。

## B. Shift endpointからのbackground clear

1. Aを通常クリック。
2. 数行離れたEを`Shift+Click`。
3. Eがkeyboard currentになった状態でtrue backgroundを通常クリック。
4. `↓` / `↑`を操作。

期待:
- [ ] selection clear後のkeyboard navigationは古いShift anchorではなく、直前のkeyboard current側から自然に続く。
- [ ] 端へjumpしない。

## C. Ctrl複数選択からのbackground clear

1. Aを通常クリックし、`Ctrl+Click`でCを追加。
2. true backgroundを通常クリックして0件にする。
3. `↓` / `↑`を操作。

期待:
- [ ] 直前のkeyboard currentを基準にnavigationする。
- [ ] 端へjumpしない。

## D. actual rubber-band回帰

- [ ] true backgroundから通常rubber-bandを開始し、選択できる。
- [ ] actual drag後に今回のfocus restoreが割り込まない。
- [ ] Ctrl rubber-band XORが従来どおり。
- [ ] Shift / Ctrl+Shiftの既確認挙動が従来どおり。
- [ ] Selection Anchor表示が従来どおり。

## E. row-whitespace / P25回帰

- [ ] 未選択行の行内余白を通常クリック → `↓` / `↑` がその行から自然に移動する。
- [ ] Shift range endpoint後の`↓` / `↑`で先頭/末尾へjumpしない。

## F. 最小UI回帰

- [ ] Window titleは`Ferry - RC 11`。
- [ ] Breadcrumb scrollbarは10px・直角・左右button常時表示。
- [ ] `Ctrl+L` ⇄ Breadcrumbは正常。
- [ ] List/Grid切替は正常。
